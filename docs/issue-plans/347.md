# #347 — explicit Jev disabling overrides

**Status:** implemented on the session branch; pending PR and merge-result CI.
This is not a completion declaration.

## Defect

`load_settings()` derived `jev_disabled` only from
`HARNESS_JEV_DISABLE`, ignoring an explicit `jev_disabled` override. It also
treated an explicitly supplied `jev_api_key=None` as absent and called
`resolve_jev_key()`, resurrecting an installed credential. A disabled CLI
preview could therefore attempt TypeSafe transport instead of staying offline.

## Contract implemented

| Input | Result |
|---|---|
| `jev_api_key` omitted | normal configured/ambient resolution |
| `jev_api_key=None` | key cleared for this Settings instance |
| `jev_disabled=True` | no key, no native dispatch |
| `jev_disabled=False` | normal resolution unless the key was cleared |
| `HARNESS_JEV_DISABLE=1`, no override | disabled; no key |
| explicit `jev_disabled=False` with env switch set | explicit Settings override wins; resolution is permitted unless the key was cleared |

The key decision happens before `Settings` construction in
`harness/config.py`, so `JevEvaluator`'s existing explicit-disable enforcement
is unchanged.

## Changes

- `harness/config.py` — explicit override precedence and omitted-vs-cleared
  distinction.
- `tests/test_config_jev_overrides.py` — nine hermetic regressions, including a
  direct `_cmd_plan` preview with `HttpTransport.post` patched to fail if any
  Jev transport is attempted.
