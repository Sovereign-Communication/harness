## Decision

Lucas decided on 2026-10-25 to use shape **(b), ledger-backed**. An ID becomes
valid when its `offer` event is recorded. This decision is fixed for this issue.

## Contract implemented

- `offer_work` and internal task creators record offers before writing task
  events.
- Every non-offer ledger append carrying a task ID checks the offer index under
  the append lock. Unknown, empty, or malformed IDs raise an explicit
  `unknown task_id` error and leave the ledger unchanged.
- External IDs are preflighted before provider dispatch at task-bound MCP,
  service, capability-probe, CLI curation, and provisioning entry points.
- The offer index is rebuilt from retained ledger history on load and repair,
  and updated on rebase and append.
- Hourglass context receipts carry their request ID; lightweight callers with
  no configured ledger remain ledger-free.

## Implementation and regression evidence

The shared guard and offer index are in [`harness/ledger.py`](../../harness/ledger.py).
MCP and CLI boundaries reject unknown external IDs before work begins; the
shared verify and dogfood services, capability probes, provisioning, and
request lifecycles distinguish generated IDs from external references.
Regression coverage drives those boundaries, including no-write assertions for
unknown IDs and the generated-ID paths, across the affected files in `tests/`.
