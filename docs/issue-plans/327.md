# #327 — gates resolve from the checkout root

**Status:** implemented on `fix/327-gate-root`; pending PR and merge-result CI.
This is not a completion declaration.

## Defect

`harness gates --run compileall` rendered `python -m compileall -q harness
tests` and executed it in the caller's working directory. From anywhere but
the repo root, `compileall` printed `Can't list 'harness'` / `Can't list
'tests'` and still exited **0** — a green gate that compiled zero files.

Reproduced before the fix from a temporary directory:

```text
$ cd "$(mktemp -d)"
$ PYTHONPATH=<checkout> python -m harness.cli gates --run compileall
rc=0
stderr:
Can't list 'harness'
Can't list 'tests'
```

The same class affected `ruff`, `unittest`, `audit`, and `jev-phase` (the
last passed `--repo-root .`). `route` had a smaller instance: its default
`packs/model_route.pack.json` was also CWD-relative, and its help did not say
so.

## Contract implemented

| Surface | Before | After |
|---|---|---|
| `ruff` | `check harness tests audits` | absolute checkout paths |
| `compileall` | `-q harness tests` | absolute checkout paths |
| `unittest` | `discover -s tests` | `discover -s <checkout>/tests` |
| `audit` | `audits/self/audit.py` | `<checkout>/audits/self/audit.py` |
| `jev-phase` | `--repo-root .` | `--repo-root <checkout>` |
| `gates --run` | inherited the caller's CWD | executes from the checkout root |
| missing gate targets | `compileall` could still exit 0 | refuses before running, naming the missing paths |
| `route` default pack | `packs/model_route.pack.json` from CWD | the checkout's pack; help says so |

`{root}` is filled from `harness.paths.REPO_ROOT`, the directory containing
the package's checkout. An installed wheel resolves to `site-packages`, where
the repo-file gates correctly refuse instead of pretending to check `harness`
and `tests`.

## Changes

- `harness/paths.py` — one checkout-root anchor.
- `harness/gate_runner.py` — `{root}` in every path-bearing gate template,
  required-target metadata, explicit root override for hermetic callers.
- `harness/cli.py` — run gates from the checkout root after checking required
  targets; resolve `route`'s default pack from the checkout.
- `harness/cli_parser.py` — route pack help names the checkout root and says
  the default is not CWD-relative.
- `tests/test_repo_root_resolution.py` — 13 regressions, including real CLI
  subprocesses from inside and outside the checkout.
