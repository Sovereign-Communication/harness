# Issue #287 — CI scheduling

**Status:** implementation and correction PRs #400/#401 are merged; post-merge CI/site checks are green. This final receipt PR closes #287 on merge; a post-merge issue comment records its merge SHA and exact evidence.

## Specification

- Cancel superseded runs for the same ref.
- Docs/site-only changes skip the five-platform hermetic test matrix while audit and other required checks remain enabled.
- Non-doc/site changes continue to run the full matrix and every existing check.
- Verify both change classes and cancellation through GitHub workflow runs.

The issue thread repeats these requirements. Its scope is clear.

## Baseline inspection

- `.github/workflows/ci.yml` already defines a per-ref concurrency group with `cancel-in-progress: true`; this behavior will be preserved and verified with consecutive pushes to the same PR.
- The workflow currently has five hermetic matrix jobs plus independent audit, package, and checkout-hygiene jobs; it has no path classification.
- Path filtering keeps the workflow active for every event. A docs/site-only change must skip the expensive hermetic setup and tests while still producing the five exact matrix contexts required by branch protection. If change detection cannot identify the base or diff, the full hermetic matrix runs.

## Implementation

`.github/workflows/ci.yml` keeps the existing workflow-level, per-ref
`cancel-in-progress: true` concurrency rule. A `changes` job classifies the
base-to-head diff and sets the matrix output. For docs/site-only changes, all
five required matrix jobs now emit a lightweight success receipt while
skipping checkout, setup, lint, compile, repo-card verification, and tests.
Code changes run the full matrix. Unknown bases, empty diffs, manual dispatches,
and change-detection failures retain the full matrix. The workflow itself stays
unfiltered; audit, package, and checkout-hygiene jobs remain independent.

## Cancellation probe finding

The first PR run started all five matrix jobs. After a follow-up push, the
older run remained active while the new run queued. Both were manually
canceled for cleanup, so this first probe did not prove automatic
cancellation. The matrix condition used `always()`, which GitHub documents
can keep work running after cancellation. It is now `!cancelled()` while
still running the matrix if the path detector fails.
