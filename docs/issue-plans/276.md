## Defect

D12 diffed `harness/` from a stored baseline commit. A squash merge could
orphan that SHA, and a baseline refreshed on a PR branch could move before the
PR merged. PR #274 reported 100% and then measured 94% after `main` moved; PRs
#296/#348 failed the audit outright on an unreachable baseline. The measurement,
not the 95% bar, was wrong.

S5 had the same shape: a ruff resolution failure read as a code failure on an
unrelated PR, and a missing tool was not distinguishable from a lint finding.

## Contract implemented

D12 now resolves the **runtime merge-base**, never a stored branch SHA:

| Context | Base |
|---|---|
| PR CI | `HARNESS_D12_BASE` = `github.event.pull_request.base.sha` |
| `main` push CI | `HARNESS_D12_BASE` = `github.event.before` |
| Local / dispatch | `git merge-base origin/main HEAD` |

The diff is taken from that merge-base to the audited tree. Executed lines come
from current-tree coverage:

- a committed `coverage_baseline.json` is a fast path **only** when its
  `commit` is exactly the resolved merge-base;
- otherwise the traced battery regenerates a temporary coverage document for
  the audited tree (or `HARNESS_D12_BASELINE` supplies one whose `commit`
  matches the base);
- a docs-only/audit-only diff short-circuits before the traced battery because
  there are no executable `harness/` lines to measure;
- no base or no coverage fails closed in CI and is a visible `SKIP
  (fail-open)` locally;
- the 95% bar is unchanged, and no hand edit of a coverage file is a valid
  substitute for executing the line.

S5 is an enforced check through the one resolver from #278:
`harness.tools.ruff_argv` (`HARNESS_RUFF` → `ruff` on `PATH` →
`<interpreter> -m ruff`). A missing tool returns one named
`S5 ruff unresolved:` failure; it is not skipped and not reported as a lint
finding.

The minimal runbook is [`docs/audit-triage.md`](../audit-triage.md): S5
signature, merge-base reproduction, and the local-only
`test_dogfood`/`test_hourglass_end_to_end` disposition. #290 extends it to
effective settings and usage questions.
