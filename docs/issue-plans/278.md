# #278 — unified external-tool resolution + preflight

**Status:** implemented on `fix/278-tool-resolution`; pending PR and
merge-result CI. This is not a completion declaration.

## Defect

Apply/verify gates executed a gate command literally. A gate written as
`python check.py` therefore required a `python` alias on `PATH`; on a
python3-only host every round failed identically, models burned their rounds,
and the task aborted as `gate_broken`. The audit's S5 ruff lookup had a
second, ad-hoc resolver with the same failure class.

## Contract implemented

One owner, `harness/tools.py`, resolves the tools every gate uses:

| Tool | Order |
|---|---|
| interpreter | `HARNESS_PYTHON`, else `sys.executable` → `python` → `python3` → `py` on `PATH` |
| ruff | `HARNESS_RUFF`, else `ruff` on `PATH` → `<interpreter> -m ruff` |

An explicit override is authoritative: when set, an unusable value is a named
error (the reason and the variable), never a silent fallback to another tool.
A caller's explicit interpreter path is left untouched. Resolution happens
once at the gate boundary:

- `gate_runner.run_gate` resolves before the shell-free `osal.run`;
- `gate_runner.validate_gate` resolves strictly, so a missing interpreter or
  ruff is one preflight error naming the fix;
- apply/verify (via `filesafety.validate_verify_command`) and dogfood call the
  same preflight, before any model round is billed;
- code-owned gate commands (`repo_scope._gate_python`) use the same token;
- the audit S5 check calls `tools.ruff_argv(strict=True)`;
- the documented-gate registry renders `{python}` and `{ruff}` through it.

Gate semantics are unchanged: only the executable's location is resolved;
arguments, cwd, exit-code mapping and the no-shell runner are untouched.
Execution keeps the runner's `(rc, output)` contract: a resolution failure is
`127` with the reason, while preflight is the loud start-up failure.

## Changes

- `harness/tools.py` — the one resolver (`resolve_python`, `python_token`,
  `ruff_argv`, `resolve_gate_argv`, `HARNESS_PYTHON`, `HARNESS_RUFF`).
- `harness/gate_runner.py` — every gate resolves through it; the ruff gate
  template is `{ruff}`; preflight resolves strictly.
- `harness/filesafety.py`, `harness/apply.py` — apply/verify preflight keeps
  the full shell-free contract and resolves known tools before spend.
- `harness/repo_scope.py` — code-owned gates use `tools.python_token()`.
- `audits/self/audit.py` — S5 uses the shared ruff resolver with a named
  failure instead of its local candidate list.
- `README.md`, `CONTRIBUTING.md` — override order and the module owner.
- `tests/test_tools.py`, `tests/test_plat_cmd_runnable.py` — the regression
  battery, including real-process runs.

The real-process cases cover:

- a `PATH` containing only a working `python3` runs a bare `python` gate;
- no interpreter (`sys.executable` unusable, empty PATH) is one named
  `no Python interpreter found` preflight error;
- `HARNESS_PYTHON` is used when `sys.executable` is unusable;
- a malformed `HARNESS_PYTHON` refuses before execution, naming the variable;
- the fizz bench task passes with only `python3` on `PATH`;
- apply refuses before any model call (`fake.calls == []`) when the
  interpreter is missing or the override is malformed.
