# Issue #288 — changed-file type checking

Issue: [#288](https://github.com/Sovereign-Communication/harness/issues/288)

## Spec and decision

Read the full issue body and its single thread comment on 2026-10-26. The
acceptance is PR-only type checking of changed Python files, a documented
baseline that leaves untouched legacy code grandfathered, a recorded choice
between Pyright and Pyrefly, and a negative control that fails on a new type
error. The thread adds no blockers or conflicting scope.

Selected **Pyright 1.1.414** after an isolated scratch trial. The supported
project floor is Python 3.9, so CI will check changed roots with
`--pythonversion 3.9`.

## Hermetic tool trial

Trial tools were installed into a temporary virtual environment outside the
repository. No project files or lockfiles were changed by the trial.

| Probe | Command/result | Exit |
|---|---|---:|
| Version | `pyright --version` → `pyright 1.1.414` | 0 |
| Untouched imported diagnostic | `pyright --pythonversion 3.11 --outputjson changed.py`; `changed.py` imports `legacy_bad` from `legacy.py`, whose body returns a string despite its `-> int` annotation. Supplying only `changed.py` returned zero diagnostics. | 0 |
| Negative control | Replaced `changed.py` with `value: int = "new error"`; the same command reported `reportAssignmentType` and one error. | 1 |
| Pyrefly comparison | `pyrefly 1.4.0`; `pyrefly check --output-format json changed.py` returned `{"errors":[]}` for the same assignment under its default no-config mode. | 0 |

The Pyrefly result is consistent with its documented basic preset, which
silences broader assignment checks in an unconfigured project. Pyright met
both required behaviors without adding checker configuration: an imported
untouched file did not become a diagnostic root, while the changed file's
deliberate assignment mismatch failed.

## Baseline mechanism

The CI job obtains the PR diff against its base SHA and passes only added,
modified, copied, or renamed `.py` files that still exist as explicit Pyright
roots. Untouched Python files are not checked as roots, so their existing
diagnostics do not block the lane. Imported modules remain available to
resolve types; the scratch trial demonstrated that an error in an imported
untouched module was not emitted. Deleted files are excluded. Docs-only PRs
skip the checker installation and invocation.

## Implementation and verification

PR/head CI, the real-job negative control, merge commit, post-merge CI, and
issue disposition evidence are appended after their runs complete.
