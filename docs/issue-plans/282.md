# Issue #282 — Playwright UI smoke and safe browser handoff

## Scope

Implement the issue's five real served-UI journeys with Playwright, one worker,
hermetic CI, and a negative control that proves an intentionally broken journey
fails. Report that the browser-tested surface is the served UI, not Electron.
The accepted design is Lucas's Option B from the issue thread: one-time browser
pairing plus persistent owner recovery.

## Implementation

- Added a persistent owner credential and a private `gui-open.url` recovery
  shortcut, plus a token-free `gui-auth-handoff.txt` note. Startup fails if it
  cannot persist the owner credential and shortcut. The server does not log
  credential values.
- Kept an optional `--auth-token` / `HARNESS_UI_AUTH_TOKEN` session credential
  separate from the persistent owner credential so it cannot displace owner
  recovery.
- Added one-time pairing codes with a five-minute expiry, single use, digest-only
  storage, same-loopback-origin redemption, bounded JSON bodies, and rate
  limiting. The UI stores the redeemed credential in browser storage when
  available and reports tab-only mode when storage is blocked.
- Replaced the bearer-token paste prompt with recovery and pairing guidance.
- Added five Playwright journeys through the served UI and real CLI fixture,
  single-worker execution, and a negative control that asserts the deliberately
  broken settings journey fails before the normal suite runs.
- Added the hermetic `ui-playwright-smoke` CI job.
- Added Chromium JavaScript and CSS rule coverage to the real Playwright run;
  the audit consumes that artifact alongside its existing Python trace. HTML
  markup is checked as parsed content through the served-page journey. The
  D12 threshold and committed baseline are unchanged.
